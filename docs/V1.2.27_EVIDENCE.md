# v1.2.27 — OpenCode V2 support via a dual export

The plugin now serves OpenCode V1 and V2 from one file. No lifecycle behaviour changed.

## Why a port was needed at all

V2 does not run V1 plugins. That was verified rather than assumed: a probe exporting **both** shapes
was loaded by OpenCode 2.0.6 and only one entrypoint was ever called.

```
module evaluated (imported)
V2 setup() CALLED      <- V2 entrypoint
                        <- V1 server() never called
```

The failure mode is the same shape as the 1.2.22 inert-plugin defect: the plugin is discovered,
imported, and then contributes nothing. The same is true of every V1 plugin, including MTPLX's own
`mtplx-session-headers.js`.

## The port

`export default { id: "longrun", server, setup }` — V1 calls `server()`, V2 calls `setup(ctx)`, and a
shared `buildTooling(input, { v2 })` produces the tool implementations once so both runtimes execute
identical logic.

Every V2 shape below was taken from the running 2.0.6 binary, not from documentation alone:

| Concern | V1 | V2 |
| --- | --- | --- |
| Entrypoint | `server(input)` | `setup(ctx)` |
| Module shape | `{ id, server }` | plain `{ id, setup }` — **no `@opencode/plugin` import needed**, so the package stays dependency-free |
| Tool registration | `tool: { longrun, longrun_verify }` | `ctx.tool.transform(editor => editor.add({ name, description, input, options }))` |
| Tool addressing | native tool call | `tools.<namespace>.<name>(args)` in the code-mode sandbox |
| Tool schema | `@opencode-ai/plugin` helpers | plain JSON Schema (`options: { namespace: "longrun", codemode: true }`) |
| `execute` args | `(args, { sessionID, directory, worktree })` | `(input, { sessionID, agent, messageID, id, progress })` — **no directory** |
| Tool result | JSON string | `{ content }` |
| Admission guard | `"tool.execute.before": (call, output)` | `ctx.tool.hook("execute.before", ev)` with `{ tool, sessionID, agent, messageID, id, input }` |
| Compaction preface | `"experimental.session.compacting"` | `ctx.session.hook("compaction", …)` |
| Events | `event: ({ event })`, `event.properties.sessionID` | `ctx.event.subscribe({ signal })`, `event.data.sessionID`, envelope `{ id, created, type, location, data }` |

Three adaptations matter for correctness rather than cosmetics:

- **`codemode: true` is required.** Without it the tool is registered and listed but not callable —
  the model is told the tool is unavailable. Discovered by probing: the same registration with and
  without the flag behaves differently.
- **V2 supplies no directory.** The tool context carries `sessionID` but not the project, so the V2
  adapter injects `ctx.location.directory`. Without it the tools would resolve runs against
  `process.cwd()` — a different project, or none.
- **Tool names are normalised.** The admission guard only understands `longrun` / `longrun_verify`,
  but V2 may present `longrun.longrun` or `longrun_longrun`, so the hook adapter maps them back.

## Verification

**303** harness regressions pass (297 prior + 6 new): `harness/test/v1227-v2-dual-export.test.mjs`
pins the dual export, both tools' registration shape, the plain-JSON-Schema requirement (including the
`action` enum surviving the helper-free path), the `{ content }` wrapping and directory injection, the
admission-hook adaptation, event subscription with a working cleanup, and inertness when disabled.

End-to-end on the real runtimes, using the installer's own output in isolated homes:

- **V2 (2.0.6):** the model called `tools.longrun.longrun({action:'help'})` and received the real
  lifecycle list (`help, start, status, receipts, next, checkpoint, verify, …`).
- **V1 (1.18.32):** the same installed file served the same request as a native tool call
  (`longrun {"action":"help"}`) and wrote its load record.

## Limits

- **The V2 compaction hook shape is unverified.** `experimental.session.compacting` maps to
  `ctx.session.hook("compaction", …)`, and the hook is accepted, but the event's payload could not be
  exercised without triggering a real compaction. The adapter accepts either plausible carrier (a
  string list or system-prompt parts) rather than guessing one.
- **`experimental.compaction.autocontinue` is NOT ported.** There is no known V2 equivalent, and the
  V1 hook governed whether OpenCode continues after a compaction. On V2 the plugin therefore does not
  enforce that continuation policy. This is a real behavioural gap, not a documentation nuance.
- **V2 tool addressing is namespace-qualified.** In V2 the tools are reached as
  `tools.longrun.longrun` / `tools.longrun.longrun_verify` from the code-mode sandbox, not as native
  tool names. Shipped command prompts written for V1 describe V1 addressing.
- **Only the tool surface and hooks were exercised.** `ctx.storage`, options, and RPC are untouched.
- MTPLX's own plugin remains V1-only, so it does not load on V2. That is outside this package; V2
  inference against MTPLX was separately confirmed to work without it.
